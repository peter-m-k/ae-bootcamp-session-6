# Quickstart: Support for Overdue Todo Items

## Prerequisites

- Dependencies installed at the repo root: `npm install`
- Both packages runnable via the existing workspace scripts (see [project-overview.md](../../docs/project-overview.md))

## Run the app

```bash
npm run start
```

This starts the backend (Express API) and frontend (React) per the existing monorepo
scripts. No new environment variables or setup steps are introduced by this feature.

## Validate the feature manually

1. Open the app and create a todo with a due date set to yesterday (or earlier), leaving
   it incomplete.
   - **Expected**: the todo card renders with the overdue color treatment
     (`--danger-color`) immediately, per [spec.md](./spec.md) User Story 1.
2. Create a todo due today, and another with no due date.
   - **Expected**: neither displays the overdue color treatment.
3. Mark the overdue todo (from step 1) complete.
   - **Expected**: the overdue color treatment is removed immediately.
4. Mark it incomplete again.
   - **Expected**: the overdue color treatment reappears immediately (due date still past).
5. Edit the overdue todo's due date to a future date and save.
   - **Expected**: the overdue color treatment is removed immediately.
6. Toggle the app's dark/light mode.
   - **Expected**: the overdue color treatment remains visually distinguishable in both
     themes (see `data-model.md` for the underlying computation and `plan.md` Technical
     Context for the theming approach).

## Run automated tests

```bash
npm test --workspace=packages/frontend
```

Covers the new `isOverdue` utility (see `data-model.md` for the computation rule) and the
updated `TodoCard` rendering tests. Refer to [tasks.md](./tasks.md) (generated by
`/speckit.tasks`) for the full breakdown of test and implementation tasks.
